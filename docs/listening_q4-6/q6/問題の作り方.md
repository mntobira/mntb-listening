# 問題の作り方（本番仕様と、整合性の守り方）

## 本番の第6問

| 設問 | 内容 | 配点 |
|---|---|---|
| 問34 | 2人の対話を聞き、**一方の話者の意見**を4択から選ぶ | 3点 |
| 問35 | **もう一方の話者の最終決定**を4択から選ぶ | 3点 |
| 問36 | 3人の会話で「**以前よりも**」その行動をしようと思っている人数 | 4点 |
| 問37 | ある発言の**根拠となる図表**を4つのグラフから選ぶ | 4点 |
| | | **合計14点** |

読み上げは A・B とも**1回のみ**。
A の対話は190〜240語・6〜10発話（交互）、
B の会話は230〜290語・8〜14発話（3人全員が2回以上）です。

2026年本試験の正答率は **A が約44%、B が約52%**。
第5問ほど極端に低くはありませんが、
「何となく聞けた気になって落とす」典型的な設問です。

## この 15 セットで守っている4つの原理

### 1. 問34：正解は必ず言い換えられている

音声で聞こえた表現をそのまま含む選択肢は、必ず誤答です。
機械でチェックしています。

- 正解の選択肢の文が対話中に**そのまま出ていたら生成が止まる**
- 言い換えの元（`heard`）が対話中に**文字どおり無ければ生成が止まる**

「聞こえた語が入っている選択肢を選ぶ」やり方では必ず外れます。

### 2. 問35：条件の「両取り」

1つの発話だけでは答えが決まりません。
**2つ以上の条件を同時に満たす**選択肢が正解で、
1つしか満たさない選択肢が誤答として並びます。

`q35.requires[]` に条件と根拠発話が入っていて、
**そのうち1つ以上は必ず最後の3発話以内**にあります（機械チェック済み）。
「最初のほうで言っていたこと」で答えると外れる設計です。

### 3. 問36：「以前よりも」が最大の引っかけ

会話中でいちばん熱心にその行動を勧める人が、実は**もともとそうしている**ため
「以前よりも」には当たらない——2026年本試験の Vicky と同じ型です。

引っかけを4型に整理し、各セットに1つ以上仕込んでいます。

| 型 | 内容 | 数える | このセット群での回数 |
|---|---|---|---|
| `alreadyDoing` | もともとその行動をしている | × | 10 |
| `soundsLikeRefusal` | 渋る言い方だが結局動く | ○ | 6 |
| `agreesButNoAction` | 同意するが自分は動かない | × | 7 |
| `conditionUnmet` | 条件つきで、その条件が満たされない | × | 4 |

**答えは人数から機械的に導いています**（手で書いていません）。
`stances[]` の `shifted` が true の人を数え、
1人→① 2人→② 3人→③ **0人→④** と決めます。

数える人数の分布：0人 3セット／1人 4セット／2人 4セット／3人 4セット

**0人（④）のセットも 3 つ**あります。
「必ず誰か1人は動く」と決めつけると落とします。

さらに機械で次を確かめています。

- `alreadyDoing` の人は `shifted: false` でなければならない
- `soundsLikeRefusal` の人は `shifted: true` でなければならない
- `agreesButNoAction` / `conditionUnmet` の人は `shifted: false`
- 引っかけを持つ話者が1人以上いる
- 数える人が3人未満のときは、数えない人の誰かに必ず引っかけがある

### 4. 問37：数字・対象・出来事の3点一致

根拠となる発言から「数字」「対象」「出来事」の3要素を取り出し、
その3つがすべて一致する図表が正解です。

```json
"basis": { "number": 42, "target": "自転車事故でけがをした学生",
           "event": "頭部のけがで搬送" }
```

各グラフに `match` があり、正解だけが3つとも `true`、
誤答は必ず1つ以上 `false` です（機械チェック済み）。

典型的な誤答の作り方：

- **数字は合うが対象が違う**（42人だが「通学手段の割合」を数えている）
- **対象は合うが出来事が違う**（学生の事故だが「月ごとの件数」）
- **出来事は合うが数字が違う**（頭部のけがだが人数が42でない）

「42という数字を探す」だけでは解けません。

| 項目 | 内容 |

| 難易度 | やや易 4 ／ 標準 7 ／ やや難 4 |
| 問37 の図表 | 縦棒グラフ 15枚／円グラフ 15枚／横棒グラフ 15枚／折れ線グラフ 15枚 |
| 問34 の正解番号 | ① 2回／② 4回／③ 6回／④ 3回 |
| 問35 の正解番号 | ① 1回／② 9回／③ 1回／④ 4回 |
| 問36 の正解番号 | ①（1人） 4回／②（2人） 4回／③（3人） 4回／④（0人） 3回 |
| 問37 の正解番号 | ① 4回／② 4回／③ 4回／④ 3回 |
| 話者の性別 | female 38人／male 37人 |
| 話者のアクセント | American 27人／British 20人／Canadian 7人／Australian 6人／Irish 5人／German 2人／French 2人／Spanish 2人／Indian 1人／Swedish 1人／Korean 1人／Dutch 1人 |
| 英文の総語数 | 7157 語 |

正解番号がひとつに偏ると勘で当たるようになるため、
4つの設問すべてで①〜④を3〜4回ずつに散らしています。
アクセントも本番同様に米・英・豪・加を中心に、非英語圏の話者も混ぜています。

## A の対話の組み立て方

1. 一方が**選択肢を4つ並べる**（`options` に入っている）
2. もう一方が**意見を述べる**（← 問34 の根拠。必ず言い換えて選択肢にする）
3. 条件のやりとりが2〜3往復
4. 最後の3発話で**決定に必要な条件が出そろう**（← 問35 の根拠）

発話は必ず交互（同じ話者が2回続かない）にしています。
本番の対話がそうなっているのと、
連続するとどちらの発言か分からなくなるためです。

## B の会話の組み立て方

1. 話題の提示（学校からの通知、新しいルールなど）
2. 3人がそれぞれの立場を出す（1人は必ず引っかけ型）
3. **数字を含む発言**が1つ入る（← 問37 の根拠）
4. 最後に各自が「これからどうするか」を言う（← 問36 の判定）

3人全員が2回以上発言します。1回しか話さない人がいると
その人の立場が判定できず、問36 が成立しません。

## 整合性をどう守っているか

データは `reference/sets6/q6setNN.json` の1か所だけにあります。
PDF もアプリ用データも作業場サイトも、すべてこの JSON から作っています。
同じ内容を2か所に書くと、片方だけ直したときに必ず食い違うためです。

その上で、機械が次を全部チェックしています。1つでも引っかかると生成が止まります。

1. **問34 の言い換え**：`heard` が対話に文字どおり存在し、正解の文は存在しない
2. **問35 の複数条件**：`requires` が2つ以上あり、根拠発話が対話に存在する
3. **問35 の決め手の位置**：`requires` の1つ以上が最後の3発話以内にある
4. **問36 の trap 整合性**：4型それぞれの `shifted` / `alreadyDoing` が矛盾しない
5. **問36 の答えの自動導出**：`shifted` の人数から答えを機械的に決める
6. **問36 の引っかけ必須**：引っかけを持つ話者が1人以上いる
7. **問37 の3点照合**：正解は3点すべて `true`、誤答は1点以上 `false`
8. **問37 の根拠発話**：`basis.utterance` が会話に文字どおり存在する
9. **解説の根拠**：`keyPhrases` や `evidence` がスクリプトに文字どおり存在する
10. **語数**：A 190〜240語・6〜10発話、B 230〜290語・8〜14発話
11. **A の交互性**：同じ話者が2回続かない
12. **B の発言回数**：3人全員が2回以上
13. **図表の種類**：1セットに4種類（棒・横棒・折れ線・円）が1枚ずつ
14. **画像プロンプト**：日本語が1文字も混じっていないか／`series` と数値が一致
15. **話者情報**：名前・性別・年齢・アクセント・役柄・トーン・推奨Voice・4つの数値
16. **全体の偏り**：難易度・図表の種類・性別・アクセント・4つの正解番号

とくに 1・4・5・7 が重要です。
1 が崩れると「聞こえた語を選ぶ」だけの問題になります。
4・5 が崩れると問36 の答えと解説が食い違い、学習者が混乱します。
7 が崩れると問37 に正解が2つできる、または0個になります。
人間が気をつけるだけでは、15セット作るうちに必ず1つ漏れます。
