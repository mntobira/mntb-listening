# 既存ファイルの変更点（変更指示書）

新規ファイルは `新規/` にそのまま入っています。コピーするだけで済みます。
このファイルは**既存ファイルを直す作業**だけを書いています。
実際のファイル名はアプリ側の作りに合わせて読み替えてください。

すでに第4問（`listening-q4`）を組み込んである場合は、
**1・2・6 だけ**やれば済みます。3〜5 は第4問のときの仕組みに
第5問ぶんを足すだけです。

## 3. 採点処理に「2問セットで完答2点」を足す

**対象**: 採点しているファイル（例 `src/lib/score.ts`）

**ここが第5問でいちばん間違いやすい所です。**
問28〜31 は4問ありますが、**問28・29 の2問で1つの得点、
問30・31 の2問で1つの得点**です。片方だけ合っていても0点で、
部分点はありません。1問1点で採点すると満点が 16点になりません。

```ts
const s = set   // listening-q5.json の sets[i]

let score = 0

// 問27（3点）
score += answers[27] === s.q27.answer ? s.q27.points : 0

// 問28〜31（2問セット×2、各完答2点）
const answerOf = (no: number) => s.q2831.blanks.find((b) => b.no === no)!.answer
for (const pair of s.q2831.pairs) {            // pairs = [[28,29],[30,31]]
  const ok = pair.every((no) => answers[no] === answerOf(no))
  score += ok ? s.q2831.pointsPerPair : 0      // 2点 or 0点
}

// 問32（4点）
score += answers[32] === s.q32.answer ? s.q32.points : 0

// 問33（5点）
score += answers[33] === s.q33.answer ? s.q33.points : 0
```

**確認**: 1セット満点が **16点** になること
（3 ＋ 2 ＋ 2 ＋ 4 ＋ 5 = 16）。

**画面表示**: 問28・29 の欄には「2問セット・完答2点」と出してください。
片方だけ合った受験者に「1点」と見せると、本番の採点と食い違います。

## 4. 選択肢は4問で1組を共有する

**対象**: 選択肢を描いている部品

**やること**: `q2831.choices` は6つで、**問28・29・30・31 の4問すべてで
同じ6つを使います**。空所ごとに別の選択肢を出す作りだと第5問になりません。

本番の指示文はこうです（そのまま画面に出してください）。

> 六つの選択肢（①〜⑥）のうちから一つずつ選びなさい。
> **同じ選択肢を2回以上使ってもかまいません。**

つまり「4つの空所には必ず別の選択肢が入る」という前提で
消去法を使わせる作りにしてはいけません。

```tsx
// 6択を1か所に出し、4つの空所すべてがそこから選ぶ
<SharedChoices items={set.q2831.choices} blanks={[28, 29, 30, 31]} />
```

`q2831.unused` には「そのセットで結果的に使われなかった選択肢」の番号が入っています。
本番は選択肢の再使用が許されるため、**この配列は空になることもあります**。
個数を前提にした表示（「使わない2つ」など）は書かないでください。
これは**解答解説のときだけ**出してください。

## 5. 音声は「1回だけ再生」にする

**対象**: 音声プレイヤーの部品（例 `src/components/AudioPlayer.tsx`）

**やること**: `playOnce: true` のときは、再生し終わったあと
もう一度押せないようにする。本番が1回読みなので、
何度も聞けると練習にならないためです。

第5問の音声は**設問ごとに区切られています**。

```
lecture.audio     … 講義（問27〜31 用）。1本
q32.audios        … 問32。A・B の2本を続けて再生（配列）
q33.audio         … 問33 の会話。2人ぶんが1本に入っている（文字列1つ）
```

`q32.audios` だけ**配列で、順に続けて鳴らしてください**。
A・B を別ファイルにしてあるのは、あとで片方だけ録り直せるようにするためです。
間は 0.5 秒くらい空けると、別々の発言だと分かります。

```tsx
// 問32：2本を順に再生する
const playSeq = async (files: string[]) => {
  for (const f of files) {
    await playOne(f)
    await wait(500)
  }
}
```

問33 は1本なので、そのまま再生するだけです。

## 6. 画像・音声の置き場所を通す

**対象**: パスを組み立てている場所

データの中の `image` は `q5set01_q33_graph.png` のような**ファイル名だけ**です。
アプリの公開フォルダの位置に合わせて、頭に付けるパスだけ調整してください。

**1セットに画像は2枚あります。**

| データの場所 | 何の画像か | いつ画面に出すか |
|---|---|---|
| `set.worksheet.image` | ワークシート（問27〜31 の空所つき） | 問27〜31 を解いている間ずっと |
| `set.q33.image` | 問33 の図表 | 問33 のときだけ |

```ts
const ws  = `/assets/listening-q5/images/${set.worksheet.image}`  // 例
const src = `/assets/listening-q5/images/${set.q33.image}`        // 例
const aud = `/assets/listening-q5/audio/${set.lecture.audio}`     // 例
```

ワークシートは画像で出すのが本番に近い見え方ですが、`set.worksheet.blocks` に
同じ内容が文字データでも入っているので、画面の幅が狭いときは文字で組んでも構いません。
その場合も空所番号 (27)〜(31) の位置は変えないでください。

## 7. 問33 は「講義・会話・図表の3つ」を同時に見せる

**対象**: 問33 の表示部分

問33 は講義の内容と、追加の会話と、図表の3つを合わせて初めて解けます。
図表だけ見せて解かせる形にすると、正解が出せません。

- 図表（`q33.image`）を画面に出す
- 会話（`q33.audios`）を聞かせる
- 講義（`lecture.audio`）は問27〜31 の段階で1回だけ流れている

`q33.graph` には図表の元データ（系列名と数値）も入っています。
画像がまだ無いときの仮表示や、読み上げ支援に使えます。
