# 問題の作り方（本番仕様と、整合性の守り方）

## 本番の第5問

| 設問 | 内容 | 配点 |
|---|---|---|
| 問27 | ワークシート冒頭の空所＝**講義の大意**。4択 | 3点 |
| 問28・29 | ワークシート前半（従来の見方・現状の問題）。**6択共通** | **2問セットで完答2点** |
| 問30・31 | ワークシート後半（利点・方策）。上と同じ6択 | **2問セットで完答2点** |
| 問32 | グループのメンバー A・B の発言が講義と一致するか | 4点 |
| 問33 | 講義＋追加の会話＋図表を統合して推論。4択 | 5点 |
| | | **合計16点** |

読み上げは**すべて1回のみ**。約150〜160 wpm。
講義は265〜290語・5段落、問32 は各8〜16語の1文、問33 の会話は55〜80語です。

## 第5問がなぜ難しいのか（2026年の正答率）

| 設問 | 正答率 |
|---|---|
| 問27 | 59.3% |
| **問28・29** | **12.7%** ← 最難 |
| 問30・31 | 35.2% |
| 問32 | 18.7% |
| 問33 | 43.7% |

問28・29 の 12.7% は、単に難しいからではありません。
**「聞こえた語をそのまま入れる」と必ず外れる**作りになっているからです。

## この 15 セットで守っている最重要ルール

**問28〜31 の正解は、講義でその語がそのまま言われることはありません。
必ず言い換えを1段挟みます。**

本番の実例：

| 音声で言っていること | 空所に入る語 |
|---|---|
| common | widespread |
| great financial rewards | profitable |
| get fewer deadly diseases | improved |
| instead of being wasted | reused |

そして**結果的に使われない選択肢は、わざと講義にそのまま出てくる語**にしてあります。
つまり「聞こえた語を入れる」やり方は、必ず失敗します。

これは機械でチェックしています。

- 正解の語が講義スクリプトに**そのまま出ていたら生成が止まる**
- 言い換えの元（`heard`）が講義スクリプトに**文字どおり無ければ生成が止まる**

人間が気をつけるだけでは、15セット作るうちに必ず1つ漏れます。

## この 15 セットの構成

| 項目 | 内容 |
|---|---|
| 難易度 | やや易 4 ／ 標準 7 ／ やや難 4 |
| 問33 の図表 | 縦棒グラフ 8／横棒グラフ 4／円グラフ 2／折れ線グラフ 1 |
| 問27 の正解番号 | ① 4回／② 5回／④ 6回 |
| 問32 の正解番号 | ① 4回／② 4回／③ 4回／④ 3回 |
| 問33 の正解番号 | ① 3回／② 5回／③ 3回／④ 4回 |
| 話者の性別 | female 37人／male 38人 |
| 話者のアクセント | American 29人／British 23人／Australian 12人／Canadian 11人 |

正解番号がひとつに偏ると勘で当たるようになるため、
3つの設問すべてで①〜④をほぼ均等に散らしています。
アクセントも本番同様に米・英・豪・加を混ぜています。

## 講義の組み立て方（5段落）

1. **導入**：何の話かを1文で定義する（← 問27 の根拠になる）
2. **従来の見方／現状の問題**（← 問28・29 の根拠）
3. **転換・仕組み**（← 問30・31 の根拠）
4. **数字**（← 問32 の判定材料）
5. **留保・結論**（← 問33 の推論材料）

段落と設問が1対1で対応しているので、
どこを聞き逃したかが受験者に分かります。

## 誤答の作り方

**問27 の3つの誤答**
- 第2段落の「従来の見方」を、結論であるかのように書いた選択肢
- only / completely / entirely などで言い過ぎにした選択肢
- 講義に無い因果関係をでっち上げた選択肢

**問32 の「一致しない」発言**
- 因果関係のすり替え（結論は正しいが理由が違う）
- 主語のすり替え（誰の話かを入れ替える）
- 数字の計算違い
- 量の言い過ぎ（some → all など）
- 講義が明確に否定していることを主張

**問33 の3つの誤答**
- 図表の読み違い（最大・最小に飛びつく）
- 講義に無い因果関係
- 言い過ぎの断定

## 整合性をどう守っているか

データは `reference/sets5/q5setNN.json` の1か所だけにあります。
PDF もアプリ用データも作業場サイトも、すべてこの JSON から作っています。
同じ内容を2か所に書くと、片方だけ直したときに必ず食い違うためです。

その上で、機械が次を全部チェックしています。1つでも引っかかると生成が止まります。

1. **問28〜31 の言い換え**：正解の語が講義にそのまま出ていないか
2. **言い換えの元**：`heard` が講義に文字どおり存在するか
3. **使わない選択肢**：`unused` が正解から機械的に導けているか（再使用があれば個数は2未満になる）
4. **選択肢の重複**：6択に同じ語が無いか（正解の重複は本番同様に許容）／英文選択肢がアルファベット順か
5. **解説の根拠**：解説に挙げた英語表現が、スクリプトに文字どおり存在するか
6. **問32 の整合**：`matches` の真偽の組み合わせが正解番号と一致するか
7. **図表の系列名**：会話または選択肢の中で言及されているか（誰も触れない系列を作らない）
8. **画像プロンプト**：日本語が1文字も混じっていないか／300字以上あるか
9. **語数**：講義265〜290語・5段落、問32 各8〜16語、問33 会話55〜80語
10. **話者情報**：性別・年齢・アクセント・役柄・トーン・推奨Voice・4つの数値が全部あるか
11. **全体の偏り**：難易度・図表の種類・性別・アクセント・3つの正解番号

とくに1・2・5 が重要です。
1と2 が崩れると第5問が第4問になってしまい、12.7%の設問を練習できません。
5 が崩れると「もっともらしいが実際には音声で言っていない」解説になり、
学習者を誤らせます。これは機械で防ぐしかありません。
