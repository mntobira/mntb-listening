## PR本文の必須欄

次の形式で、判断は必ずどちらか一つのみ記載する。

```
リスニング配布判断: リスニングにも送ってください。
リスニング配布理由: 共通ガチャの重複補償を修正するため。
リスニング対象: src/components/GachaRoom.tsx、関連テスト
リスニング受け渡し状況: 未送付。差分ZIPを作成し、リンクと適用手順を共有予定。
```

送らない場合の判断は `リスニング配布判断: リスニングには送らないでください。`。
化学など統合版専用の変更だけなら、その理由と「対象なし」を記載。
PRの追加push・説明文の更新時も判断を見直し、古い対象ファイルや検証状況を残さない。
PRテンプレートと `node scripts/check-listening-pr.mjs --pr <番号>` で記載漏れ／両方選択を検査する。
GitHub Appにworkflows更新権限がなくCI登録は拒否されたため、自動実行は未有効。`docs/listening-handoff.workflow.yml` は管理者が登録するための定義。自動化・マージ必須化には管理者による配置とブランチ保護設定が必要。

## 配布判断の目安

- **原則送る**：ガチャ、コイン、ショップ、きせかえ、共通ナビ、認証、フレンド、対戦、ランキング、音声、保存、セキュリティ、共通依存関係。
- **原則送らない**：リスニングに関係しない化学／理科／数学などの教材だけの変更。
- **要個別確認**：統合版ホーム、教科一覧、Firebase、独自アセット。リスニング専用UIや専用設定に丸ごと上書きしない。

## 受け渡し手順

1. PRに判断・理由・対象・送付状況を明記。
2. 共通ファイルと専用テンプレートの双方への影響を確認する。
3. 新規のコピー先へ生成し、教材・音源・対戦・単語/文法補助・画面・保存の検証を行う。
4. 初回移行前は新版の全体ZIPを渡してよい。分岐先で編集が始まったら差分パッチと適用手順を優先する。
5. ZIP、複製元コミット、対象パス、検証結果、必要なルール反映、未実施項目を伝える。
6. 実際に送付していない限り「送付済み」「反映済み」と記載しない。送付と適用完了も区別する。

## 専用版の構成方針

リスニング演習と復習を主軸にし、オンライン対戦は力試しの入口として維持する。
単語・英文法はリスニングを助ける短い基礎学習に限定し、別教科・別対戦・大量のメニューに増やさない。
専用ホームと補助学習はテンプレート側で進化させ、統合版のホームは保つ。
