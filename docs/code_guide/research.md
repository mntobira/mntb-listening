## 7. コード地図（写真で掴む）について

### 7.1 何を作ったか

- `maps/00-overview.png`：しくみの箱12個ごとのファイル数・行数、よく使われる中心ファイル4つ、箱どうしの import の本数の表。
- `maps/01〜24-*.png`：箱ごとに1マス＝1ファイル（40マスを超える箱はフォルダの区切りで分割）。マスには ファイル名・ひとことで・タグの色・行数の棒・「使われる／使う」の import 数、6ファイル以上から使われるものは紺の太枠、要確認・変わったものには印。下に、その絵の中の import のつながり（最大24本）。
- `codemap.md`：同じ中身を1ファイル1行の文字にしたもの（約600行）。

### 7.2 どこまで短くなるか（正直なところ）

- **短くなること**：「どこに何があるか」「どれが中心か」「どの箱とどの箱がつながっているか」を掴む最初の段階。これまでは ls → いくつかのファイルを開く → 冒頭を読む、を繰り返していた部分を、地図1〜2枚で済ませられる。目的のファイルに当たりを付けてから開くので、開くファイルの数が減る。
- **短くならないこと**：関数の中身、条件分岐、型、数値などの細部。絵のマスは「ひとことで」の要約なので、正確さは元のファイルに及ばない。直す・確かめる作業では、必ず元のファイルを読む。
- **AI に読ませる場合**：量は文字版 `codemap.md` が画像の約半分（7.4）。正確さも実際に AI に画像を読ませて測った（7.4）。数字は全部合っていたが、ファイル名の2.3%が実在しない名前に化けた。画像は人が一目で全体を掴むため、文字の索引は AI と検索のため、と使い分ける。
- 地図はコードから自動で作るので、リファクタリングのたびに `update.sh` で作り直せば古くならない。ただし「ひとことで」は人が書いた文なので、役割が変わったファイルは 6.4 の手順でカードを直す必要がある。

**ここから言えること**
- 数字（行数・import 数）とフォルダは、この6枚では全部正しく読めた。「どの辺りに・どれくらいの大きさのファイルがあるか」を掴む目的には、画像でも足りる。
