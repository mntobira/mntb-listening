# コードの図鑑（docs/code_guide）

リポジトリのファイルを1つずつ「〜をする係」として説明した資料。数字・図・日付・コミットは、すべて今のコードから作り直せる。

| ファイル | 中身 |
|---|---|
| `interactive.html` | ブラウザで開く図鑑（1ファイル・外部通信なし）。しくみの図／ユーザーの流れ／フォルダの木／検索／タグ／一般向け・エンジニア向け |
| `maps/*.png` | **コード地図**。全体1枚＋しくみの箱ごと24枚。1マス＝1ファイル（名前・ひとことで・タグ・行数・import 数）。ファイルを開く前に「どこに何があるか」を掴むための絵 |
| `codemap.md` | コード地図の文字版（1ファイル1行）。AI に渡す・検索するならこちら。画像の約半分の量で、パスは写し間違いが起きない（画像を AI に読ませた実測では、ファイル名の2.3%が実在しない名前に化けた。research.md 7.4） |
| `poster.png` | 全体の1枚絵（目的・規模の数字・しくみの図） |
| `file-guide.pdf` | 全カードの手引き（A4・フォルダごとの章） |
| `research.md` | 数字の数え方・分類の方針・要確認の一覧・リファクタリングの反映記録・自己チェック |

## コードを読むとき（地図を先に見る）
1. `maps/00-overview.png` で、関係する箱（画面と部品／対戦のしくみ／採点・記録の計算 …）を決める
2. その箱の地図で、紺の太枠（6ファイル以上から使われる中心ファイル）と名前から 2〜5 ファイルに絞る
3. 絞ったファイルだけを開く。細部（条件分岐・型・数値）は必ず元のファイルで確かめる（地図の文は要約）

## リファクタリングのあとに作り直す
```
bash docs/code_guide/tools/update.sh           # 作り直し＋自己チェック
bash docs/code_guide/tools/update.sh --check   # ＋ブラウザでの動作確認（1280px・390px、動きあり／なし）
```
- 終わると「新しいファイル／消えたファイル／見直し候補（冒頭の説明・export・行数が変わったカード）／図の箱が未定」が出る（`data/sync.json` にも残る）
- 新しいファイルは仮カード（確信度「低」）で載る → `cards/*.txt` に本物のカードを書く
- 見直し候補は差分を見てカードを直し、`python3 docs/code_guide/tools/build_cards.py --accept <パス…>` で確認済みにする
- 初回はフォント（Google Fonts の M PLUS Rounded 1c・JetBrains Mono）と Playwright を `.work/` に取ってくる。`.work/` は Git に入れない

## 材料と道具
- `cards/*.txt` … 1行1枚のカード（パス｜タグ｜確信度｜ひとことで｜くわしく(任意)）。ここを直すのが基本
- `data/bundles.py` … まとめて1枚にするファイル群の規則
- `data/basis.json` … カードを書いたときの根拠（冒頭の説明と export のハッシュ・行数）。見直し候補の判定に使う
- `tools/` … `build_cards.py`（事実の取り出し・差分）→ `enrich.py`（図の箱・数字）→ `build_maps.py`（コード地図）→ `build_site.py` / `build_poster.py` / `build_pdf.py` → `render.mjs`（PNG・PDF・ブラウザ確認）→ `selfcheck.py`
- 場所はすべて `tools/paths.py` がこのフォルダの位置から決める。別の作業ツリーを説明したいときは `CODE_GUIDE_SRC=<パス>`
