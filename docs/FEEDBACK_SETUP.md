# ユーザーフィードバック収集機能 セットアップガイド（Google スプレッドシート版）

タイトル画面と各結果画面に設置した「ご意見・ご要望」を、**Google スプレッドシートに 1 行ずつ自動で溜めていく**ための手順書です。

- 所要時間：**10 分程度**
- 必要なもの：Google アカウント（`mntobira@gmail.com` でログインした状態が想定）
- アプリのコードを書き換える作業は **ありません**（設定するのは環境変数 1 行だけ）

---

## ⚠️ 現在の状況（2026-08-02 時点の実測）

ご提供いただいた GAS のウェブアプリ URL

```
https://script.google.com/macros/s/AKfycbxZh6AeCP6nmfdq6AUmeh_OlKQjdBJx2nZSOA02k1F_XA-a-MiKEa9CaVxDquSfDaxEtQ/exec
```

は **アプリ側に登録済み**（`src/utils/feedback.ts` の `DEFAULT_FEEDBACK_WEBHOOK_URL`）ですが、
サーバーから実際に POST して確認したところ **HTTP 401（Sorry, unable to open the file at this time.）** が返ります。

これは GAS のデプロイ設定が

| 項目 | 現在（推定） | あるべき値 |
| --- | --- | --- |
| アクセスできるユーザー | 自分のみ／組織内 | **全員** |

になっていることを示します。**この 1 か所を直すだけで送信が通るようになります。**

### 直し方（2 分）

1. スプレッドシート →［拡張機能］→［Apps Script］
2. 右上［デプロイ］→［**デプロイを管理**］
3. 対象デプロイの **鉛筆アイコン（編集）** をクリック
4. 「アクセスできるユーザー」を **全員** に変更
   （「次のユーザーとして実行」は **自分** のまま）
5. バージョンを **「新バージョン」** にして［デプロイ］
   → **URL は変わりません**
6. ブラウザでその `/exec` URL を開き、`ChemNote feedback endpoint is running.` と表示されれば完了

> 💡 判定は **`/exec` URL をブラウザで開くだけ**でできます（→ STEP 7）。
> Google のログイン画面に飛んだり 401 になる場合は、公開設定が「全員」になっていません。
>
> （※ 以前アプリ内にあった「お問い合わせの送信状態」の欄は廃止しました。
> 送信に失敗した分は端末に退避され、起動時・オンライン復帰時に**自動で再送**されるため、
> 利用者が診断操作をする必要がなくなったからです。）

## 0. 全体像（30 秒で把握する）

```
   生徒がアプリで送信
        │
        ├──▶ ① Firestore `feedback` コレクション … 常時ON。消えない保管庫（設定不要）
        │
        └──▶ ② Google Apps Script（Web アプリ）
                    └──▶ ★ Google スプレッドシート「feedback」タブに1行追記
                             （必要になれば ここからメール通知もONにできる）

   ↑ 両方失敗したときだけ ③ 端末に退避して自動再送 ＋「メールで送る」ボタンを提示


   【別経路】アプリを起動したとき（初回＋24時間ごと）
        ├──▶ ① Firestore `app_users`（uid を ID にして 1人1件で上書き）
        └──▶ ② 同じ GAS → スプレッドシート「users」タブに 1人1行で上書き
              → **行数がそのまま総ユーザー数**、C 列で Google 連携済みを数えられる（→ 11-2）
```

- 今回設定するのは **②** です。
- ①は既に動いており、②の設定に失敗している間もご意見は失われません。
- **①と②のどちらか片方だけ失敗した場合も、失敗した側だけを自動で再送します**（重複行は増えません）。

## 1. STEP 1 — 受け取り用スプレッドシートを作る

1. [https://sheets.new](https://sheets.new) を開く（新しいスプレッドシートが即作成されます）
2. 左上のファイル名を分かりやすい名前に変更する
   例：`まなとび フィードバック`
3. タブ名は触らなくて構いません。**`feedback` タブはスクリプトが自動生成します。**

> 📌 このスプレッドシートには**返信用メールアドレスなどの個人情報が入る**ため、共有設定は「自分のみ」（既定）のままにしてください。

---

## 2. STEP 2 — Apps Script エディタを開く

作成したスプレッドシートで

**［拡張機能］→［Apps Script］**

を選びます。新しいタブでエディタが開き、`function myFunction() {}` だけが書かれた `コード.gs` が表示されます。

> ⚠️ **`script.google.com` から単体で作らないでください。**
> ここから開くと「このスプレッドシートに紐づいたスクリプト」になり、STEP 4 の `SPREADSHEET_ID` 設定が不要になります。

---

## 3. STEP 3 — スクリプトを貼り付ける

1. エディタに表示されている中身を **すべて削除**（`Ctrl`/`Cmd` + `A` → `Delete`）
2. 本リポジトリの **[`docs/feedback-gas.js`](./feedback-gas.js) の全文をそのまま貼り付け**
3. `Ctrl`/`Cmd` + `S` で保存

---

## 4. STEP 4 — CONFIG を確認する

貼り付けたコードの上部にある `CONFIG` を確認します。**スプレッドシート運用なら、既定値のままで変更は不要です。**

```js
var CONFIG = {
  // ---- スプレッドシートに記録する（既定：ON） ----
  APPEND_SHEET: true,        // ← true のままにする
  SHEET_NAME: 'feedback',    // ← 記録先タブ名（自動作成）
  SPREADSHEET_ID: '',        // ← STEP 2 の手順なら空のままでOK

  // ---- メールでも通知する（既定：OFF） ----
  SEND_EMAIL: false,         // ← 今回は false（メール通知は使わない）
  NOTIFY_EMAIL: 'mntobira@gmail.com',

  SHARED_SECRET: '',
};
```

| 項目 | 既定値 | 変更が必要な場合 |
|------|--------|------------------|
| `APPEND_SHEET` | `true` | **変更不要**（これが今回の主役） |
| `SHEET_NAME` | `'feedback'` | タブ名を変えたいときだけ |
| `SPREADSHEET_ID` | `''` | **`script.google.com` から単体でスクリプトを作った場合のみ**、シート URL の `/d/【ここ】/edit` を貼る |
| `SEND_EMAIL` | `false` | 後述「9. 後からメール通知も足す」参照 |

---

## 5. STEP 5 — `testFeedback()` で動作確認（★重要）

デプロイの前に、**スクリプト単体でシートに書けるか**を確かめます。ここを飛ばすと「アプリからは送れているのにシートに入らない」原因切り分けが難しくなります。

1. エディタ上部の関数プルダウンで **`testFeedback`** を選ぶ
2. **［実行］** をクリック
3. 初回のみ承認ダイアログが出ます
   - 「権限を確認」→ アカウントを選択
   - 「このアプリは Google で確認されていません」→ **［詳細］→［(安全ではないページ)に移動］**
     （自分が書いたスクリプトなので問題ありません）
   - 「許可」を押す
4. スプレッドシートのタブに戻ると **`feedback` タブが生成され、見出し行＋テスト行が 1 行**入っています
5. 確認できたら **テスト行（2 行目）は削除**してください

> ✅ ここで行が増えれば、スプレッドシート書き込みは完全に動いています。
> ❌ 行が増えない／エラーになる場合は、エディタ下部の実行ログのメッセージを確認してください。
> `記録先のスプレッドシートが見つかりません` と出た場合は STEP 2 をやり直す（または `SPREADSHEET_ID` を設定する）必要があります。

2. 左の歯車 **［種類の選択］→「ウェブアプリ」**

## 7. STEP 7 — URL をブラウザで開いて自己診断する

コピーした `/exec` の URL を**ブラウザのアドレス欄に貼って開く**と、次のような診断結果が表示されます。


| 表示 | 意味 | 対処 |
|------|------|------|
| `sheet: OK (feedback)` | シート接続 OK。**この状態が正解** | — |
| `users: OK (users, N人)` | 利用者台帳 OK。**N がそのまま登録ユーザー数** | — |
| `sheet: NG - ...` | シートに書けない | STEP 4 の `SPREADSHEET_ID` を見直す |
| ログイン画面に飛ぶ／エラーページ | 公開設定が「全員」でない | STEP 6-3 をやり直す |

## 8. STEP 8 — アプリ側に URL を設定して再ビルド

プロジェクト直下の `.env`（無ければ `.env.example` をコピーして作成）に 1 行追記します。

```bash
VITE_FEEDBACK_WEBHOOK_URL=https://script.google.com/macros/s/AKfycb.................../exec
```

そのうえで再ビルドします。

```bash
npm run build
```

> ⚠️ **本番サイトにも同じ環境変数が必要です。**
> `VITE_` から始まる変数は**ビルド時に埋め込まれる**ため、ローカルの `.env` に書くだけでは公開サイトに反映されません。
> Vercel / Netlify / Cloudflare Pages / GitHub Actions など、**実際にビルドしている場所の環境変数設定にも同じ 1 行を登録**してから再デプロイしてください。
> （このリポジトリにはフロントエンドのホスティング設定が含まれていないため、デプロイ先の管理画面で設定します）

### 設定できているかの確認（コード不要）

アプリでフィードバックのモーダルを開くと、フォーム下部に送信先が表示されます。

| 表示 | 状態 |
|------|------|
| `送信先：アプリの管理データベース（Firestore）` | **未設定**（環境変数が読めていない） |
| `送信先：アプリの管理データベース（Firestore） ／ Google スプレッドシート／メール通知` | **設定完了** ✅ |

未設定のままなら、`.env` の記述ミス（クォート・スペース・末尾の `/exec` 抜け）か、再ビルドしていないかのどちらかです。

## 10. Firestore ルールの反映（初回のみ・必須）

`firestore.rules` に **`feedback`（意見）** と **`app_users`（利用者台帳）** の 2 つのルールを追加しています。**未反映のままだと Firestore 側への保存が失敗します**（シートには届きますが、二重の保管庫の片方が欠けます）。

```bash
firebase deploy --only firestore:rules
```

> **この 1 回のコマンドで両方が有効になります。**
> `app_users` は「総ユーザー数」と「登録されている Google アカウント」を数えるためのコレクションです（→ [11-2](#11-2-総ユーザー数と登録-google-アカウントの把握users-タブ)）。
> 未反映のままでもアプリは普通に動きますが、Firestore 側の人数集計だけができません（スプレッドシートの `users` タブには届きます）。

### `feedback` に追加したルールの要点

- `allow create` のみ許可（**未ログインのゲストでも送信可能**）
- `allow read, update, delete: if false` — クライアントからは読めない／消せない
- フィールド構成を `hasOnly` で固定し、想定外のデータ混入を拒否
- `message` は 1〜2000 文字、`rating` は 0〜5 の整数、`screen` / `category` は既知の値のみ
- `uid` は「ログイン中の本人の uid」か `null`（ゲスト）のみ → **なりすまし不可**
- `createdAt` は `request.time` 固定 → 端末時計の偽装で並び順を荒らせない

### `app_users` に追加したルールの要点

- **ドキュメント ID = uid** の 1 人 1 件。何度起動しても行（ドキュメント）は増えない
  → **ドキュメント数がそのまま総ユーザー数**になる
- `allow create` / `allow update` のみ（本人の uid のドキュメントに限る）→ **なりすまし不可**
- `allow read, delete: if false` — クライアントからは読めない／消せない
  （※このためアプリ画面内に「総ユーザー数」を表示する機能は付けていません。理由は 11-2 の最後に記載）
- `lastSeenAt`（最終利用）は `request.time` 固定 → 端末時計の偽装ができない
- `firstSeenAt`（初回登録）は作成時のみ `request.time`、更新時は**書き換え禁止**
- フィールド構成を `hasOnly` で固定し、各文字列に長さ上限を設定

## 11. スプレッドシートの列構成

`feedback` タブには次の 15 列が記録されます。

| 列 | 見出し | 内容 |
|----|--------|------|
| A | 受信日時 | GAS がリクエストを受けた時刻（サーバー時刻） |
| B | 管理ID | 1 件ごとの一意な ID（Firestore の文書 ID と一致） |
| C | 送信画面 | タイトル画面／単元の結果画面／模擬試験の結果画面 |
| D | 種類 | よかった点／問題・解説の内容／不具合・表示崩れ／要望・改善案／その他 |
| E | 評価 | 満足度の**数値のみ**（1〜5・必須入力）。`AVERAGE(E:E)` でそのまま平均が取れる |
| F | 内容 | 本文（折り返し表示・列幅広め） |
| G | 返信用メール | 任意入力。ここに書いてあれば返信できる |
| H | ユーザー名 | ログイン中の表示名（ゲストは「ゲスト」） |
| I | uid | Firebase の uid（ゲストは空） |
| J | ログインメール | Google ログインのメール |
| K | 付帯情報 | 送信画面ごとの状況（下表）を JSON で保持 |
| L | アプリ版 | `VITE_APP_VERSION` |
| M | 画面サイズ | `390x844` などの実表示サイズ |
| N | UserAgent | 端末・ブラウザ情報 |
| O | 端末送信日時 | 生徒の端末時刻（オフライン再送の判別に使う） |

### 使いこなしのヒント

- **絞り込み**：1 行目を選んで［データ］→［フィルタを作成］→ C 列や D 列で絞る
- **重要な意見に印を付ける**：P 列以降は自由に使えます（追記は A〜O 列にしか行われないため、自作の列が壊れることはありません）
- **並び順**：新しいものが下に追加されます。A 列で降順ソートすると最新順になります
- **満足度の平均**：空いているセルに `=AVERAGE(E:E)` と入れるだけで出ます（E 列は数値で記録しているため）

## 11-2. 総ユーザー数と登録 Google アカウントの把握（`users` タブ）

同じスプレッドシートに `users` タブが自動生成され、**1 人 1 行**で利用者が記録されます。

> **行数（見出し行を除く）＝ 総ユーザー数** です。
> 同じ人が何度アプリを開いても行は増えません（`uid` をキーに上書きするため）。

| 列 | 見出し | 内容 |
|----|--------|------|
| A | 初回登録日時 | 初めて記録された日時（以後、上書きされません） |
| B | 最終利用日時 | 最後にアプリを開いた日時（**離脱者の判別に使えます**） |
| C | Google連携 | `連携済み` / `ゲスト` |
| D | メールアドレス | **登録されている Google アカウント**（ゲストは空） |
| E | Google表示名 | Google アカウントの名前 |
| F | アプリ内ニックネーム | プロフィールで設定した名前 |
| G | 学年 | プロフィールで設定した学年 |
| H | 連続学習日数 | 記録時点の streak |
| I | 修了章数 | 記録時点の修了章数 |
| J | uid | Firebase の uid（ゲストは匿名の端末ID） |
| K | アカウント作成日 | Google アカウントを連携した日 |
| L | アプリ版 | `VITE_APP_VERSION` |
| M | UserAgent | 端末・ブラウザ情報 |

### すぐ使える集計式

| 知りたいこと | 数式 |
|---|---|
| 総ユーザー数 | `=COUNTA(J2:J)` |
| Google 連携済みの人数 | `=COUNTIF(C:C,"連携済み")` |
| ゲストのままの人数 | `=COUNTIF(C:C,"ゲスト")` |
| 連携率 | `=COUNTIF(C:C,"連携済み")/COUNTA(J2:J)` |
| 直近 7 日に使った人数 | `=COUNTIFS(B:B,">="&TODAY()-7)` |
| 平均の連続学習日数 | `=AVERAGE(H:H)` |

### 記録されるタイミング

送信しすぎてシートが膨らまないよう、**次の 2 回だけ**記録されます。

1. そのアカウントで**初回**に記録するとき
2. 前回の記録から**24 時間以上**あいた最初の起動

### 動作確認

Apps Script エディタで関数 `testUserRecord` を選んで［実行］すると、`users` タブにテスト行が 1 行増えます。
**2 回実行しても行が増えなければ**「1 人 1 行の上書き」が正しく動いています（確認後、その行は削除してください）。

### 別の確認方法（スプレッドシートを使わない場合）

- **Firebase コンソール → Firestore → `app_users`**：ドキュメント数が総ユーザー数
- **Firebase コンソール → Authentication → Users**：Google ログイン済みアカウントの一覧

> **なぜアプリの画面に「総ユーザー数」を表示しないのか**
> `app_users` には全利用者のメールアドレスが並びます。アプリから件数を読めるようにするには
> Firestore のルールで読み取りを開ける必要があり、「件数だけ許可する」という書き方は存在しません。
> 総数を表示するためだけに全員のメールアドレスを露出させるのは割に合わないため、
> 閲覧は運営側の手段（上記）に限定しています。

## 12. 設置場所と自動で付く情報

| 画面 | 場所 | 付帯情報（K 列） |
|------|------|------------------|
| **タイトル画面**（`Home.tsx`） | 「学習ノート」「アプリ紹介」と並ぶカード | 連続学習日数、解答済み問題数／総問題数、ゲストか否か |
| **単元の結果画面**（`Explanation.tsx`） | 結果スコアカード内・ランキングの下 | 単元 ID、単元名、モード、合計スコア、正解数／採点対象数、所要時間 |
| **模擬試験の結果画面**（`MockExam.tsx`） | 「もう一度解く／選択に戻る」ボタンの下 | 得点、満点、正答率、所要時間、時間超過フラグ |

他の画面に足したい場合も 1 行で追加できます。

```tsx
import { FeedbackButton } from './FeedbackButton';

<FeedbackButton screen="chapter_result" variant="inline" context={{ chapterId }} />
```

`variant` は `card`（横長カード）／`inline`（ピル型ボタン）／`text`（テキストリンク）の 3 種類です。

## 13. 通信失敗時のふるまい（意見を取りこぼさない設計）

1. **送信先ごとに成否を判定**します。「Firestore は成功したがシートだけ失敗」という場合、**失敗したシート側だけ**を `localStorage`（キー `feedback_outbox_v1`、最大 20 件）へ退避します。
   → 再送時に Firestore へ二重登録されることはありません。
2. すべての送信先が失敗した場合は、その場で「**メールで送る**」ボタンを提示します（宛先・本文・端末情報が差し込まれた `mailto:`）。
3. 次回アプリ起動時（起動 2.5 秒後）と**オンライン復帰時**に自動で再送します（`flushFeedbackQueue`）。

電波の悪い教室や機内モードで書かれた意見も、後から確実にシートへ届きます。

## 14. 収集される情報

**必須入力は本文だけ**です。氏名・メールアドレスは任意で、未入力でも送信できます。

- 入力値：満足度（**必須**・1〜5）、種類、本文、返信用メール（任意）
- 自動付与：送信元画面、画面固有の付帯情報（上表）、ログイン中なら uid・表示名・ログインメール、送信日時、UserAgent、画面サイズ、アプリ版、管理 ID

### 利用者台帳（`users` タブ / `app_users`）で集めている情報

意見フォームとは別に、**人数を数えるためだけ**の記録を残しています（→ 11-2）。

- uid、Google 連携の有無、Google 表示名・メールアドレス（連携している場合のみ）
- アプリ内のニックネーム・学年・連続学習日数・修了章数
- 初回登録日時／最終利用日時、アプリ版、UserAgent

**学習の記録・スコア・ランキングには一切影響しません。** 記録は 1 人 1 行の上書きで、起動ごとに増えることはありません。

## 15. 後からメール通知も足したい場合

「シートに溜めるのは続けたいが、届いたらすぐ気づきたい」となったときは、**アプリ側の変更は不要**です。

1. Apps Script エディタで `SEND_EMAIL: false` → **`true`** に変更して保存
2. **［デプロイ］→［デプロイを管理］→ 鉛筆アイコン → バージョン「新バージョン」→［デプロイ］**
   （URL は変わらないので、`.env` の書き換えも再ビルドも不要です）
3. 初回のみメール送信の権限承認が必要な場合があります（`testFeedback` を実行して承認）

逆に「シートは要らない、メールだけ」にしたい場合は `APPEND_SHEET: false` にして再デプロイします。

## 16. よくあるトラブル

| 症状 | 原因 | 対処 |
|------|------|------|
| シートに何も増えない | `.env` の `VITE_FEEDBACK_WEBHOOK_URL` が未設定／ビルドしていない | STEP 8 をやり直す。**本番は再デプロイが必要** |
| アプリは「送信できました」なのにシートが空 | 公開設定が「全員」でない | STEP 6-3 を修正 →「新バージョン」で再デプロイ |
| `/exec` を開くと Google ログインに飛ぶ | 同上 | 同上 |
| `sheet: NG - ...` と出る | スクリプトがシートに紐づいていない | STEP 2 をやり直す、または `SPREADSHEET_ID` を設定 |
| GAS を直したのに反映されない | 保存しただけでは公開版は変わらない | 「デプロイを管理」→「新バージョン」で再デプロイ |
| Firestore コンソールに残っていない | ルールが未反映 | `firebase deploy --only firestore:rules` |
| 評価の平均（`AVERAGE(E:E)`）が出ない | 旧バージョンの GAS が `5 / 5` という**文字列**で書いていた | 新しい `docs/feedback-gas.js` を貼り直して**新バージョンで再デプロイ**。既存の行は手作業で数値に直す |
| `users` タブができない | 旧バージョンの GAS のまま | 同上（貼り直し→新バージョンで再デプロイ）。`/exec` を開いて `users: OK` が出れば成功 |
| `users` タブの行が起動ごとに増える | 通常は起きない（uid で上書きしている） | `uid` 列（J 列）に空欄がないか確認。空欄の行は手作業で削除 |
| 行が 2 件ずつ増える | GAS を 2 回デプロイして URL を 2 つ登録している | 不要なデプロイをアーカイブする |
